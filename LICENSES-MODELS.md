# Licences: models, libraries and fonts used by the image engine

Rule: only permissive licences (MIT, Apache-2.0, BSD, SIL OFL for fonts). No AGPL, GPL, LGPL, non-commercial or "research only" code or weights. Every entry was checked against the **upstream repository**, not a mirror's or a registry's claim.

## Models

`npm run check:licenses` reads `scripts/models.manifest.json` (the single source of truth for model files), the installed npm packages and the bundled fonts, and fails on anything not permissive or unclear. It also fails if a blocked model has a file on disk, or if a model is missing from this page.

### BiRefNet_lite: MIT

- Upstream repository `ZhengPeng7/BiRefNet`: `LICENSE` is MIT. The model card of `ZhengPeng7/BiRefNet_lite` on Hugging Face also says `license: mit`. Both say the weights are MIT, so this is explicit, not inferred.
- The ONNX file comes from the author's own GitHub release, not from a mirror. A copy on `onnx-community` exists; I compared it and the fp32 file is byte-identical, so the mirror adds nothing. Its fp16 variant (about 109 MB) is **not used**: I did not verify it and half-precision masks were not part of the brief.
- **Doubt (training data):** the weights are MIT, but the model was trained on public segmentation datasets (DIS5K, DUTS and others, listed in the paper). Some of those datasets have their own terms. The authors license their weights as MIT and do not claim a restriction, and I found nothing contradicting that. I cannot rule out a downstream claim from a dataset owner. If you plan to sell this as a product, this is the line to have a lawyer read.
- **We ship a rewritten copy, not the original.** The original has `Concat` operators with up to 1,024 inputs, and WebGPU allows at most 16 storage buffers per shader (8 on many GPUs). `scripts/split-concat.mjs` rewrites the graph so no `Concat` or `Split` is wider than 8 (50 wide `Split` nodes and 629 `Concat` nodes touched, 408 nodes added). No weight changes. The upstream URL, upstream sha256 and our sha256 are all pinned in the manifest and re-checked in the browser before the model is used. The licence is the same MIT; the MIT notice must travel with it.
- The file is **not** committed (`public/models/` is gitignored); `npm run fetch:models` downloads it and builds the split copy.

### ISNet general-use: unclear, therefore blocked and never downloaded

- `xuebinqin/DIS` (the authors): `LICENSE.md` is Apache-2.0, and the README says the **code and the evaluation metric** are Apache-2.0. It does **not** say what licence covers the trained weights.
- The weights were trained on **DIS5K**, whose terms of use allow non-commercial research use only. Whether that carries into the weights is a legal question I cannot answer, and the brief says unclear means not used.
- The widely used `isnet-general-use.onnx` file comes from `danielgatis/rembg` (MIT code), which re-hosts weights it did not train; its MIT licence covers rembg's code, not the weights. A registry or mirror calling it Apache-2.0 does not settle the authors' position.
- Status in the manifest is `blocked`. `BgRemover.load()` refuses it with this reason and downloads nothing; `check:licenses` fails if a copy of it ever appears in `public/models/`. **It stays blocked until you say otherwise.** Options that would settle it: written confirmation from the DIS authors that the weights are Apache-2.0, or you accepting the risk in writing.

### Runtime and other libraries added in Step 4

| Package | Version | Licence | Why |
|---|---|---|---|
| onnxruntime-web | 1.22.0 (pinned) | MIT (`microsoft/onnxruntime` LICENSE; the package declares MIT) | Runs ONNX models in the browser on WebGPU or WASM. Chosen over Transformers.js because we need a model file we control, our own pre- and post-processing and a worker with exact backend choice; Transformers.js would add a larger dependency tree for a feature we only need one function of. 1.22.0 is pinned because it was the newest version where WebGPU got as far as running a model on the test machine (see IMAGE_STATUS.md). Its `.wasm` and `.mjs` runtime files are copied to `public/ort/` by `fetch:models` so nothing loads from a CDN |

Everything else installed (125 packages in total, dev tools included) was checked by script: MIT, BSD, Apache-2.0, ISC and similar. One exception is listed on purpose and printed every run: **`lightningcss` (MPL-2.0)**, a CSS tool that Vite uses at build time. It is not shipped in the app and we do not modify it, but MPL-2.0 is not on your permissive list, so it is here for you to decide, not decided silently.

Where the font files came from: the `@fontsource/schibsted-grotesk` and `@fontsource/instrument-sans` npm packages (used only to download the files; they are **not** dependencies). Fontsource ships the upstream fonts converted to woff2 and cut down to the Latin character range.

**Unclear or to watch**
- The fontsource files are the upstream fonts subsetted by a third party. The OFL allows that, and the upstream OFL text is shipped next to the files, but I did not diff the glyph outlines against the upstream TTFs.
- Latin subset only. Cyrillic, Greek, Vietnamese and most symbols (including the right arrow →) fall back to a system font. If a brand needs them, add the `latin-ext` or other subsets from the same packages.
